# DP2 GAaP 1.0 FlexZBoost Stage 2: Clipped RTN-124 Model

This document describes how to run photo-z estimation on the LineA Apollo
cluster after the six-band GAaP 1.0 FlexZBoost pickle has been generated by
`dp2_stage1_train_instructions_clipped.md`.

The input dataset is the LSST DP2 primary Object catalog stored on Apollo as
individual parquet shards:

```text
/data/cl/lsst/dp2/primary/catalogs/object
```

The directory contains files such as:

```text
object_6309_lsst_cells_v2_LSSTCam_runs_DRP_DP2_v30_0_8_DM-55060_stage3_20260606T114559Z.parq
object_9974_lsst_cells_v2_LSSTCam_runs_DRP_DP2_v30_0_8_DM-55060_stage3_20260609T183945Z.parq
```

All parquet files are expected to have the same schema, including:

```text
u_gaap1p0Flux, g_gaap1p0Flux, r_gaap1p0Flux
i_gaap1p0Flux, z_gaap1p0Flux, y_gaap1p0Flux
u_gaap1p0FluxErr, g_gaap1p0FluxErr, r_gaap1p0FluxErr
i_gaap1p0FluxErr, z_gaap1p0FluxErr, y_gaap1p0FluxErr
ebv, coord_ra, coord_dec, objectId
```

During estimation, `rail-estimate` converts the nJy fluxes to AB magnitudes and
magnitude uncertainties, then applies the SFD correction from `ebv`. The
resulting in-memory columns are named `{band}_gaap1p0Mag_sfd` and
`{band}_gaap1p0MagErr_sfd`. These names differ from the Stage 1 parquet columns
only by the `_sfd` suffix; both represent dereddened GAaP 1.0 photometry.

For each band, the transformation is:

```text
mag_ab      = 31.4 - 2.5 * log10(flux_nJy)
mag_err     = (2.5 / ln(10)) * abs(fluxErr_nJy / flux_nJy)
mag_ab_sfd  = mag_ab - R_band * ebv
```

with `R_band = [4.81, 3.64, 2.70, 2.06, 1.58, 1.31]` in `ugrizy` order.
The deterministic SFD correction does not change `mag_err`. A non-finite or
non-positive flux produces `NaN` magnitude and uncertainty; the FlexZBoost
estimator then replaces that magnitude and its uncertainty with the configured
band limit and `1.0`, respectively.

The Stage 1/Stage 2 feature contract is:

| Property | Stage 1 training | Stage 2 estimation |
|---|---|---|
| band order | `u, g, r, i, z, y` | `u, g, r, i, z, y` |
| magnitude template | `{band}_gaap1p0Mag` | `{band}_gaap1p0Mag_sfd` |
| effective features | `i, u-g, g-r, r-i, i-z, z-y` | same |
| non-detection marker | `NaN` | `NaN` from invalid/non-positive flux |
| magnitude limits | `26.5, 27.8, 27.1, 26.7, 25.8, 24.6` | same |
| magnitude errors used as features | no | no |
| redshift grid | 601 points over `[0, 6]` | same |

## 1. Create the run directory

Create an isolated run directory under `/scratch`:

```bash
source /scripts/$(whoami)/ondemand/env-dp2-gaap1p0.sh

```

Copy or link the model pickle produced by

export PZ_STAGE1_RUN=$PZ_RUN_ROOT/dp2-stage1-fzboost-gaap1p0-clipped

cp "$PZ_STAGE1_RUN/training-model/model_dp2_v3p1_fzboost_dp2_6band_gold.pickle" \
   "$PZ_APOLLO_RUN/model/"

Set the canonical paths used by the commands below:

```bash
export PZ_DP2_INPUT_DATASET=/data/cl/lsst/dp2/primary/catalogs/object

export PZ_OUTPUT_DIR=$PZ_APOLLO_RUN/output
export PZ_LOG_DIR=$PZ_APOLLO_RUN/log
```

Copy the Stage 1 `environment-freeze.txt` into the model directory as well and
compare it with the active Stage 2 environment. Training and estimation must
use the same validated package set, even though that set may be newer than the

```bash
cp "$PZ_STAGE1_RUN/training-model/environment-freeze.txt" \

  "$PZ_APOLLO_RUN/model/environment-freeze-stage1.txt" \
  "$PZ_APOLLO_RUN/model/environment-freeze-stage2.txt"
```

Continue only if `diff` produces no differences. Keep both manifests with the
run artifacts.

Create the estimator configuration used by every command in this stage:

```bash
cat > "$PZ_APOLLO_RUN/fzboost_dp2_v3p1_6band_gold_estimate.yaml" <<'YAML'
zmin: 0.0
zmax: 6.0
nzbins: 601
nondetect_val: .nan
mag_limits:
  u_gaap1p0Mag_sfd: 26.5
  g_gaap1p0Mag_sfd: 27.8
  r_gaap1p0Mag_sfd: 27.1
  i_gaap1p0Mag_sfd: 26.7
  z_gaap1p0Mag_sfd: 25.8
  y_gaap1p0Mag_sfd: 24.6
include_mag_err: false
YAML

export PZ_ESTIMATE_CONFIG=$PZ_APOLLO_RUN/fzboost_dp2_v3p1_6band_gold_estimate.yaml
```

The magnitude-limit keys intentionally use the Stage 2 `_sfd` names. RAIL
looks up limits using the active `--column-template`, so using the unsuffixed
Stage 1 keys here would not reproduce the training non-detection transform.

## 3. Run a single-file smoke test

This verifies the model, flux-to-magnitude conversion, SFD correction, and
retained-column output before launching the full dataset. `rail-estimate` reads
only the required parquet columns, so the other Object-table fields are not
loaded into memory.

```bash
cd "$PZ_APOLLO_RUN"
export PZ_FIRST_INPUT=$(cat first-input.txt)
mkdir -p "$PZ_APOLLO_RUN/smoke"

rail-estimate \
  "$PZ_FIRST_INPUT" \
  "$PZ_APOLLO_RUN/smoke/smoke-test.hdf5" \
  --algorithm=fzboost \
  --calibration-file="$PZ_MODEL" \
  --bins=601 \
  --param-file="$PZ_ESTIMATE_CONFIG" \
  --sfd-deredden \
  --column-template='{band}_gaap1p0Mag_sfd' \
  --column-template-error='{band}_gaap1p0MagErr_sfd' \
  --row-id-column=objectId \
  --output-columns=i_gaap1p0Mag_sfd
```

Inspect the smoke-test output:

```bash
python - <<'PY'
import h5py

path = "smoke/smoke-test.hdf5"
with h5py.File(path, "r") as handle:
    for name in ("meta/xvals", "data/yvals", "ancillary/i_gaap1p0Mag_sfd"):
        dataset = handle[name]
        print(name, dataset.shape, dataset.dtype)
    assert handle["data/yvals"].shape[0] == handle["ancillary/i_gaap1p0Mag_sfd"].shape[0]
    assert handle["data/yvals"].shape[1] == 601
    integrity = handle["pz_compute"]
    assert bool(integrity.attrs["complete"])
    assert integrity.attrs["row_count"] == handle["data/yvals"].shape[0]
    assert integrity.attrs["row_id_column"] == "objectId"
    assert "row_id_fingerprint" in integrity.attrs
PY
```

The `ancillary/i_gaap1p0Mag_sfd` dataset is carried into both final products by
`pz-build-hats` in stage 3.

## 5. Create the Slurm array script

Create a small array-job runner. Each array task processes exactly one parquet
file and writes one HDF5 output. `rail-estimate` projects only the 12 GAaP 1.0
flux fields plus `ebv` and `objectId`, creates the SFD-corrected magnitude
columns once, and reuses them for inference and optional output retention.

```bash
cd "$PZ_APOLLO_RUN"

cat > run-one-dp2-gaap1p0-estimate.sh <<'EOF'
#!/usr/bin/env bash
#SBATCH --job-name=dp2-pz-gaap1p0
#SBATCH --partition=cpu_photoz
#SBATCH --account=hpc-photoz
#SBATCH --mem=40G
#SBATCH --time=12:00:00
#SBATCH --output=log/slurm-%A_%a.out
#SBATCH --error=log/slurm-%A_%a.err

set -euo pipefail

source /scripts/$(whoami)/ondemand/env-dp2-gaap1p0.sh

: "${PZ_DP2_INPUT_DATASET:?missing PZ_DP2_INPUT_DATASET}"
: "${PZ_MODEL:?missing PZ_MODEL}"
: "${PZ_ESTIMATE_CONFIG:?missing PZ_ESTIMATE_CONFIG}"
: "${PZ_OUTPUT_DIR:?missing PZ_OUTPUT_DIR}"
: "${PZ_FILE_LIST:?missing PZ_FILE_LIST}"

input_file=$(sed -n "$((SLURM_ARRAY_TASK_ID + 1))p" "$PZ_FILE_LIST")
if [ -z "$input_file" ]; then
    echo "No input file for SLURM_ARRAY_TASK_ID=$SLURM_ARRAY_TASK_ID" >&2
    exit 1
fi
export input_file

relative_path="${input_file#$PZ_DP2_INPUT_DATASET/}"
output_file="$PZ_OUTPUT_DIR/${relative_path%.parq}.hdf5"
mkdir -p "$(dirname "$output_file")"

if [ -f "$output_file" ]; then
    if python - "$output_file" <<'PY'
import h5py
import sys

with h5py.File(sys.argv[1], "r") as handle:
    rows = handle["data/yvals"].shape[0]
    marker = handle["pz_compute"].attrs
    valid = (
        bool(marker.get("complete", False))
        and int(marker.get("row_count", -1)) == rows
        and "row_id_fingerprint" in marker
        and handle["data/yvals"].shape[1] == 601
        and "ancillary/i_gaap1p0Mag_sfd" in handle
        and handle["ancillary/i_gaap1p0Mag_sfd"].shape[0] == rows
    )
raise SystemExit(0 if valid else 1)
PY
    then
        echo "Complete output already exists: $output_file"
        exit 0
    fi
    backup="${output_file}.incomplete-${SLURM_JOB_ID}-${SLURM_ARRAY_TASK_ID}"
    mv "$output_file" "$backup"
    echo "Moved incomplete output to $backup"
fi

echo "SLURM_JOB_ID=$SLURM_JOB_ID"
echo "SLURM_ARRAY_TASK_ID=$SLURM_ARRAY_TASK_ID"
echo "input_file=$input_file"
echo "output_file=$output_file"
echo "model=$PZ_MODEL"
echo "estimate_config=$PZ_ESTIMATE_CONFIG"

rail-estimate \
  "$input_file" \
  "$output_file" \
  --algorithm=fzboost \
  --calibration-file="$PZ_MODEL" \
  --bins=601 \
  --param-file="$PZ_ESTIMATE_CONFIG" \
  --sfd-deredden \
  --column-template='{band}_gaap1p0Mag_sfd' \
  --column-template-error='{band}_gaap1p0MagErr_sfd' \
  --row-id-column=objectId \
  --output-columns=i_gaap1p0Mag_sfd
EOF

chmod +x run-one-dp2-gaap1p0-estimate.sh
bash -n run-one-dp2-gaap1p0-estimate.sh
```

## 6. Submit a pilot array job

Before using the whole cluster, run a pilot job with the five largest parquet
files, measured by file size. File size is only a proxy for the in-memory load,
but selecting the largest shards is a more useful stress test than selecting
the first files in the manifest. This checks the Slurm array script, model
loading, memory requirement, output layout, and logs without starting the full
catalog run.

The runner fixes the LineA Slurm partition to `cpu_photoz`, the account to
`hpc-photoz`, and the memory reservation to 40 GB per task.

```bash
cd "$PZ_APOLLO_RUN"

while IFS= read -r input_file; do
  printf '%s\t%s\n' "$(stat --format='%s' "$input_file")" "$input_file"
done < input-parquet-files.txt |
  LC_ALL=C sort -t $'\t' -k1,1nr -k2,2 > input-parquet-files-by-size.txt

awk -F '\t' 'NR <= 5 {sub(/^[^\t]*\t/, ""); print}' \
  input-parquet-files-by-size.txt > pilot-parquet-files.txt

mkdir -p "$PZ_APOLLO_RUN/output-pilot"

export PZ_FILE_LIST=$PZ_APOLLO_RUN/pilot-parquet-files.txt
export PZ_NFILES=$(wc -l < "$PZ_FILE_LIST")
export PZ_OUTPUT_DIR=$PZ_APOLLO_RUN/output-pilot
export PZ_MAX_CONCURRENT=5

test "$PZ_NFILES" -eq 5

sbatch \
  --partition=cpu_photoz \
  --account=hpc-photoz \
  --mem=40G \
  --array=0-$((PZ_NFILES - 1))%$PZ_MAX_CONCURRENT \
  --export=ALL,PZ_DP2_INPUT_DATASET="$PZ_DP2_INPUT_DATASET",PZ_MODEL="$PZ_MODEL",PZ_ESTIMATE_CONFIG="$PZ_ESTIMATE_CONFIG",PZ_OUTPUT_DIR="$PZ_OUTPUT_DIR",PZ_FILE_LIST="$PZ_FILE_LIST" \
  run-one-dp2-gaap1p0-estimate.sh
```

Save the job id printed by `sbatch`:

```bash
export PZ_ARRAY_JOB_ID=<jobid>
```

Watch the job:

```bash
squeue -u "$(whoami)"
```

After the pilot finishes, inspect the pilot outputs:

```bash
sacct -j "$PZ_ARRAY_JOB_ID" --format=JobID%30,JobName%25,State,ExitCode,Elapsed,MaxRSS
find "$PZ_APOLLO_RUN/output-pilot" -name '*.hdf5' | sort
grep -R "Traceback\\|Error:\\|CondaError\\|Killed\\|OOM\\|out of memory" log || true
```

Before submitting production, reset `PZ_OUTPUT_DIR` to the production output
directory:

```bash
export PZ_OUTPUT_DIR=$PZ_APOLLO_RUN/output
```

## 7. Submit the full-cluster production job

For the final run over the complete DP2 catalog, scale the array concurrency
using three inputs:

- the historical large `pz-compute` defaults documented in this repository;
- the current Apollo partition layout documented by LineA;
- the observed memory requirement from the pilot run.

The previous production defaults in this repository used:

```text
-N 26 -n 2032
```

for `fzboost` and similar single-process estimators. That corresponds to about
78 concurrent `rail-estimate` processes per node.

The `cpu_photoz` partition, submitted under the `hpc-photoz` account, exposes
all 28 Apollo compute nodes. Their memory layout is:

- 16 nodes `apl[01-16]` with 128 GB RAM each;
- 12 nodes `apl[17-28]` with 256 GB RAM each.

This workflow starts with a 40 GB reservation per task. The pilot over the five
largest parquet files in Section 6 is the acceptance test for that reservation:
all five tasks must finish with state `COMPLETED`, exit code `0:0`, valid HDF5
outputs, and no memory errors before the production array is submitted.

Because Slurm must place each task within one node, calculate capacity by
rounding down the number of 40 GB tasks that fit on each node, rather than by
dividing the cluster-wide aggregate RAM:

```text
16 nodes * floor(128 GB / 40 GB) = 16 * 3 = 48 tasks
12 nodes * floor(256 GB / 40 GB) = 12 * 6 = 72 tasks
total theoretical memory capacity = 48 + 72 = 120 concurrent tasks
```

Reserve a 5% concurrency margin and round to the nearest integer:

```text
round(0.95 * 120) = 114 concurrent tasks
```

Use this limit for the production array:

```bash
cd "$PZ_APOLLO_RUN"

export PZ_FILE_LIST=$PZ_APOLLO_RUN/input-parquet-files.txt
export PZ_NFILES=$(wc -l < "$PZ_FILE_LIST")
export PZ_MAX_CONCURRENT=114

sbatch \
  --partition=cpu_photoz \
  --account=hpc-photoz \
  --mem=40G \
  --array=0-$((PZ_NFILES - 1))%$PZ_MAX_CONCURRENT \
  --export=ALL,PZ_DP2_INPUT_DATASET="$PZ_DP2_INPUT_DATASET",PZ_MODEL="$PZ_MODEL",PZ_ESTIMATE_CONFIG="$PZ_ESTIMATE_CONFIG",PZ_OUTPUT_DIR="$PZ_OUTPUT_DIR",PZ_FILE_LIST="$PZ_FILE_LIST" \
  run-one-dp2-gaap1p0-estimate.sh
```

Save the job id printed by `sbatch`:

```bash
export PZ_ARRAY_JOB_ID=<jobid>
```

If the cluster is busy, or if the run shows memory pressure or filesystem
contention, reduce only the concurrency cap, for example:

```bash
export PZ_MAX_CONCURRENT=80
```

The configured cap of `114` is 95% of the theoretical memory-limited capacity.
Do not increase it above the theoretical limit of `120` without revisiting the
per-node placement calculation and the observed task memory.

This document uses a Slurm array rather than the legacy `pz-compute.batch`
dispatcher because each array task reads its input parquet directly, writes a
final output path ending in `.hdf5`, and preserves the input relative path.
The historical `pz-compute` defaults are useful as a CPU-scale reference, but
the final concurrency is capped by the `cpu_photoz` partition memory and by the
observed per-task memory requirement.

## 8. Resume failed or missing outputs

After the array job finishes, build a retry list containing missing or incomplete outputs:

```bash
cd "$PZ_APOLLO_RUN"

python - <<'PY'
from pathlib import Path
import os

root = Path(os.environ["PZ_DP2_INPUT_DATASET"])
out_root = Path(os.environ["PZ_OUTPUT_DIR"])

invalid = []
for line in Path("input-parquet-files.txt").read_text(encoding="utf-8").splitlines():
    input_path = Path(line)
    relative = input_path.relative_to(root)
    output_path = out_root / relative.with_suffix(".hdf5")
    valid = False
    if output_path.exists():
        try:
            import h5py
            with h5py.File(output_path, "r") as handle:
                rows = handle["data/yvals"].shape[0]
                marker = handle["pz_compute"].attrs
                valid = (
                    bool(marker.get("complete", False))
                    and int(marker.get("row_count", -1)) == rows
                    and "row_id_fingerprint" in marker
                    and handle["data/yvals"].shape[1] == 601
                    and "ancillary/i_gaap1p0Mag_sfd" in handle
                    and handle["ancillary/i_gaap1p0Mag_sfd"].shape[0] == rows
                )
        except (KeyError, OSError):
            valid = False
    if not valid:
        invalid.append(line)

Path("retry-parquet-files.txt").write_text(
    "\n".join(invalid) + ("\n" if invalid else ""), encoding="utf-8"
)
print("missing or incomplete outputs:", len(invalid))
PY
```

If `missing or incomplete outputs` is greater than zero, resubmit only those files. The runner preserves any incomplete HDF5 with an `.incomplete-*` suffix before retrying:

```bash
export PZ_FILE_LIST=$PZ_APOLLO_RUN/retry-parquet-files.txt
export PZ_NFILES=$(wc -l < "$PZ_FILE_LIST")
export PZ_MAX_CONCURRENT=114

if [ "$PZ_NFILES" -gt 0 ]; then
  sbatch \
    --partition=cpu_photoz \
    --account=hpc-photoz \
    --mem=40G \
    --array=0-$((PZ_NFILES - 1))%$PZ_MAX_CONCURRENT \
    --export=ALL,PZ_DP2_INPUT_DATASET="$PZ_DP2_INPUT_DATASET",PZ_MODEL="$PZ_MODEL",PZ_ESTIMATE_CONFIG="$PZ_ESTIMATE_CONFIG",PZ_OUTPUT_DIR="$PZ_OUTPUT_DIR",PZ_FILE_LIST="$PZ_FILE_LIST" \
    run-one-dp2-gaap1p0-estimate.sh
fi
```

## 9. Inspect outputs

While the job is still running, summarize the active array state without
treating `RUNNING` or `PENDING` tasks as failures:

```bash
cd "$PZ_APOLLO_RUN"

: "${PZ_ARRAY_JOB_ID:?set PZ_ARRAY_JOB_ID to the Slurm array job id}"

squeue -j "$PZ_ARRAY_JOB_ID" || true
sacct -j "$PZ_ARRAY_JOB_ID" --format=JobID%30,JobName%25,State,ExitCode,Elapsed,MaxRSS

sacct -j "$PZ_ARRAY_JOB_ID" --parsable2 --noheader \
  --format=JobID%30,State,ExitCode,Elapsed,MaxRSS |
awk -F'|' -v job="$PZ_ARRAY_JOB_ID" '
  $1 ~ "^" job "_[0-9]+$" {
    total += 1
    states[$2] += 1
    if ($2 !~ /^(COMPLETED|RUNNING|PENDING)$/) {
      failed += 1
      print "failed or terminal non-success array task:", $0 > "/dev/stderr"
    }
  }
  END {
    print "array tasks seen by sacct:", total
    for (state in states) {
      print state, states[state]
    }
    if (failed > 0) {
      exit 1
    }
  }
'
```

Check that every Slurm array task completed successfully. For an array job
`181552`, this checks task records such as `181552_0` through
`181552_<number of input files - 1>`:

```bash
cd "$PZ_APOLLO_RUN"

: "${PZ_ARRAY_JOB_ID:?set PZ_ARRAY_JOB_ID to the Slurm array job id}"

squeue -j "$PZ_ARRAY_JOB_ID" || true
sacct -j "$PZ_ARRAY_JOB_ID" --format=JobID%30,JobName%25,State,ExitCode,Elapsed,MaxRSS

sacct -j "$PZ_ARRAY_JOB_ID" --parsable2 --noheader \
  --format=JobID%30,State,ExitCode,Elapsed,MaxRSS |
awk -F'|' -v job="$PZ_ARRAY_JOB_ID" '
  $1 ~ "^" job "_[0-9]+$" {
    total += 1
    states[$2] += 1
    if ($2 != "COMPLETED" || $3 != "0:0") {
      bad += 1
      print "non-success array task:", $0 > "/dev/stderr"
    }
  }
  END {
    print "array tasks:", total
    for (state in states) {
      print state, states[state]
    }
    if (total == 0 || bad > 0) {
      exit 1
    }
  }
'
```

Summarize the total elapsed time for the array. `wall-clock elapsed` is the
real time from the first task start to the last task end; `sum task elapsed` is
the accumulated runtime across all array tasks:

```bash
cd "$PZ_APOLLO_RUN"

: "${PZ_ARRAY_JOB_ID:?set PZ_ARRAY_JOB_ID to the Slurm array job id}"

sacct -j "$PZ_ARRAY_JOB_ID" --parsable2 --noheader \
  --format=JobID%30,State,ExitCode,Start,End,ElapsedRaw \
  > array-sacct-timing.txt

python - <<'PY'
from datetime import datetime
import os
from pathlib import Path

job = os.environ["PZ_ARRAY_JOB_ID"]
starts = []
ends = []
sum_elapsed = 0
tasks = 0

for line in Path("array-sacct-timing.txt").read_text(encoding="utf-8").splitlines():
    if not line:
        continue
    parts = line.rstrip("\n").split("|")
    if len(parts) != 6:
        continue
    jobid, state, exit_code, start, end, elapsed_raw = parts
    if not jobid.startswith(f"{job}_") or "." in jobid:
        continue
    suffix = jobid.rsplit("_", 1)[-1]
    if not suffix.isdigit():
        continue
    if state != "COMPLETED" or exit_code != "0:0":
        continue
    if start in ("Unknown", "None") or end in ("Unknown", "None"):
        continue
    starts.append(datetime.fromisoformat(start))
    ends.append(datetime.fromisoformat(end))
    sum_elapsed += int(elapsed_raw)
    tasks += 1

if tasks == 0:
    raise SystemExit("No completed array tasks found in sacct output")

wall = int((max(ends) - min(starts)).total_seconds())
print("completed array tasks:", tasks)
print("first task start:", min(starts).isoformat(sep=" "))
print("last task end:", max(ends).isoformat(sep=" "))
print("wall-clock elapsed seconds:", wall)
print("sum task elapsed seconds:", sum_elapsed)
PY
```

## 11. Expected Apollo production outputs

The run directory should contain:

```text
$PZ_APOLLO_RUN/model/model_dp2_v3p1_fzboost_dp2_6band_gold.pickle
$PZ_APOLLO_RUN/fzboost_dp2_v3p1_6band_gold_estimate.yaml
$PZ_APOLLO_RUN/input-parquet-files.txt
$PZ_APOLLO_RUN/run-one-dp2-gaap1p0-estimate.sh
$PZ_APOLLO_RUN/smoke/smoke-test.hdf5
$PZ_APOLLO_RUN/output/object_*.hdf5
$PZ_APOLLO_RUN/log/slurm-*.out
$PZ_APOLLO_RUN/log/slurm-*.err
```

These outputs can be passed to `pz-build-hats` with the original DP2 parquet
dataset as the input directory and the stage 2 HDF5 tree as the output
directory. `pz-build-hats` matches files by relative path, for example:

```text
input:  $PZ_DP2_INPUT_DATASET/object_6309_...parq
output: $PZ_OUTPUT_DIR/object_6309_...hdf5
```

The association with `objectId`, `coord_ra`, and `coord_dec` is positional:
row `i` in the input parquet is matched to row `i` in `data/yvals` from the
corresponding HDF5 output.

The estimation stage is successful when:

- the single-file smoke test writes `smoke/smoke-test.hdf5`, outside the
  production output tree;
- the full Slurm array finishes without failed tasks;
- the number of output HDF5 files matches the number of input parquet files;
- a sampled output contains `meta/xvals`, `data/yvals`, and
  `ancillary/i_gaap1p0Mag_sfd`;
- logs do not contain unresolved tracebacks or repeated `rail-estimate` errors.
